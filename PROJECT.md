## 1. Architecture & Core Invariants

Gadispot is a high-concurrency parking marketplace platform operating in urban India (launching in Bengaluru). It connects vehicle drivers seeking guaranteed parking with space owners (residential driveways, commercial lots, gated societies). The platform uses an **in-process Modular Monolith** on **Python FastAPI**, a single cross-platform **Flutter** mobile client (serving Drivers, Space Owners, and Security Guards), **PostgreSQL 16 with PostGIS** for spatial data and authoritative concurrency, and **Redis 7+** for caching and rate limiting.

### Architectural Invariants:
1. **Mathematical Double-Booking Exclusion (PostgreSQL GiST):**
   - Double-bookings are prevented directly at the storage engine level via PostgreSQL `btree_gist` extension, `tstzrange` types, and an exclusion constraint:
     ```sql
     CONSTRAINT prevent_overlapping_active_reservations
     EXCLUDE USING gist (
         parking_space_id WITH =,
         time_window WITH &&
     ) WHERE (status IN ('ACTIVE_HOLD', 'CONFIRMED', 'ACTIVE_SESSION', 'MAINTENANCE_BLOCK', 'OWNER_BLACKOUT'));
     ```
   - Redis must never serve as the authority for booking correctness.
2. **The 480-Second Hold Policy (`POL-HLD-01`):**
   - Checkout holds have an authoritative lifespan of strictly **480 seconds (8 minutes)**. Two-tier expiration: Tier 1 background worker running every 5 seconds (`FOR UPDATE SKIP LOCKED`) plus Tier 2 inline opportunistic sweep.
3. **Double-Entry General Ledger & Deadlock-Free Zero Child Lock Protocol:**
   - Append-only double-entry general ledger with a 9-account Chart of Accounts. Every posted journal satisfies $\sum \text{Debits} = \sum \text{Credits}$ with $\ge 2$ lines (`trg_verify_journal_balance`).
   - Zero Child Lock Protocol: Posting trigger validates child line balance via an MVCC snapshot without child row locks; child mutations acquire `FOR SHARE` locks on parent entries. The directed wait-for graph is a strict DAG, mathematically eliminating deadlocks.
   - Posted journals and lines are strictly immutable (`trg_prevent_posted_modification`, `trg_prevent_posted_lines_mod`). Reversals execute via compensating entries.
4. **Cryptographic Separation of Payment QR and Parking Access QR:**
   - **Payment QR:** Generated by gateway/switch, encodes NPCI UPI transaction URI (`upi://pay?pa=...`), 480-second TTL, scanned by driver UPI app to transfer funds.
   - **Parking Access QR:** Minted by backend using 128-bit CSPRNG entropy (`spx_ent_...` / `spx_ext_...`), scanned by guard app via `mobile_scanner`, atomically burned (`CONSUMED`) upon entry. Zero financial or personal PII is exposed to guards.
5. **Durable Webhook Idempotency:**
   - Payment webhooks are deduplicated via unique constraint `(gateway_name, gateway_event_id)` on `payment_webhook_events`. Duplicates return HTTP 200 without duplicate database mutations.
6. **DPDPA 7-Day Gate Photo Data Minimization:**
   - Offline admission photos in subterranean cellular dead zones are uploaded to private S3 buckets and permanently purged by an automated S3 Lifecycle rule within **7 days**, retaining only the immutable SHA-256 audit hash.

## 4. Interface Contracts

### 4.1 FastAPI ↔ PostgreSQL 16 / PostGIS Contract
- **Connection Driver:** Asynchronous binary protocol using `asyncpg` (v0.30.0) with SQLAlchemy 2.x async engine (`postgresql+asyncpg://`).
- **Connection Lifecycle:** Managed via FastAPI application lifespan (`asynccontextmanager` in `backend/app/main.py`). Session-scoped connection pool (min 10, max 30 connections) with 10s connection timeout and TCP keepalives.
- **Transaction Boundaries:** Cross-domain operations (e.g. hold creation + reservation insertion, or payment capture + journal posting) execute within explicit database transactions (`async with session.begin():`).
- **Schema Authority:** All DDL derives strictly from version-controlled Alembic migrations (`backend/alembic/`). Hand-written test DDL strings are prohibited.
- **Spatial Interface:** Geospatial coordinates stored as `GEOMETRY(Point, 4326)`. Spatial queries use PostGIS operators (`ST_DWithin`, `ST_DistanceSphere`) backed by spatial GiST indexes.
- **Concurrency & Locking:** Booking temporal exclusion enforced via PostgreSQL GiST constraint `prevent_overlapping_active_reservations`. Ledger posting locks parent rows exclusively and verifies line balance via MVCC without child line locks; child line mutations acquire `FOR SHARE` locks on parent entries.

### 4.2 FastAPI ↔ Redis 7+ Contract
- **Connection Driver:** Asynchronous Redis client (`redis-py` async interface).
- **Non-Authoritative Role:** Redis is strictly non-authoritative for financial state or booking exclusion. The database engine is the sole source of truth.
- **Primary Use Cases:**
  1. *Rate Limiting:* Sliding-window rate limiting on OTP requests (3 per 15 min), login attempts, and search queries (`ratelimit:{user_id|ip}:{action}`).
  2. *Token Revocation Blocklist:* Storage of revoked JWT jti tokens with TTL matching token expiry (`jwt:blocklist:{jti}`).
  3. *In-Flight Hold Presentation:* Cached active hold countdown timers for mobile UI presentation (`hold:presentation:{reservation_id}`).
  4. *Ephemeral Shift Schedules:* Guard 8-hour shift arrival schedules cached for rapid API response (`guard:shift:{property_id}:{date}`).

### 4.3 FastAPI ↔ Payment Gateways & Open-Source Hyperswitch Contract
- **Port Abstraction (`PaymentGatewayPort`):** Typed abstract base class defining `create_order`, `verify_webhook_signature`, `process_refund`, and `disburse_payout`.
- **Pluggable Adapters:**
  1. `RazorpayAdapter`: Primary P0 gateway; creates orders via REST API; verifies raw HMAC-SHA256 signatures with secret key.
  2. `CashfreeAdapter`: Secondary P0 standby gateway; provides automated bank payouts via Cashfree Payouts API.
  3. `HyperswitchAdapter`: Open-source Universal Payment Orchestration Platform (Juspay, Apache-2.0, Rust); provides dynamic routing and failover across acquirers.
  4. `UpiDirectAdapter`: Open-source dynamic UPI QR generator via Python `qrcode[pil]`.
- **Webhook Ingestion Contract:**
  - Endpoint: `POST /api/v1/webhooks/{gateway}`.
  - Signature Verification: Verified against raw HTTP request bytes before JSON deserialization.
  - Idempotency: Event recorded in `payment_webhook_events` with unique `(gateway_name, gateway_event_id)`. Duplicates return HTTP 200 immediately with zero database mutations.
- **Refund Lifecycle State Machine:**
  - Transitions through `REFUND_ELIGIBLE` $\to$ `REFUND_REQUESTED` $\to$ `GATEWAY_ACCEPTED` $\to$ `REFUND_PROCESSING` $\to$ `REFUND_SETTLED` (or `REFUND_FAILED`).

### 4.4 FastAPI ↔ Flutter Mobile Client Contract
- **Protocol:** HTTPS RESTful API conforming to OpenAPI 3.1 specification.
- **Error Standard:** All API error responses conform strictly to RFC 7807 Problem Details:
  ```json
  {
    "type": "https://api.gadispot.com/errors/conflict",
    "title": "Exclusion Violation",
    "status": 409,
    "detail": "The selected parking space was claimed by another driver.",
    "code": "SLOT_ALREADY_RESERVED",
    "instance": "/api/v1/bookings/hold",
    "timestamp": "2026-11-05T11:35:00Z"
  }
  ```
- **Authentication Header:** Standard `Authorization: Bearer <access_token>`. Unauthenticated requests return HTTP 401; unauthorized role actions return HTTP 403.
- **Mutating Request Idempotency:** All mutating requests (`POST /bookings/hold`, `POST /access/validate-scan`) require an `Idempotency-Key` UUID header.
- **Zero App Secrets:** Zero payment gateway secret keys, Firebase service account credentials, or database connection strings are bundled in the mobile application binary.
